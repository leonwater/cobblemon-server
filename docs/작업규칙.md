# 업데이트 작업 규칙

요청받은 수정 작업을 할 때마다 이 순서와 규칙을 지킵니다.

## 대화 규칙

- 항상 **한국어**, **짧은 문장**으로 보고한다. 작업 중 진행 상황 한 줄·질문·오류 설명도 모두 한국어 (영어 금지).
- 모르는 것은 **"모르겠다"**고 말한다. 추측으로 채우지 않는다.
- **모르는 것은 작업하지 않는다.** 어디·무엇인지 먼저 묻는다.
- 사용자가 제시한 방향과 **부득이하게 다르게** 가야 하면, **먼저 의견을 묻고 확답**을 받은 뒤 작업한다.
- 시도마다 **데드라인**을 정한다. 넘기면 **안 되는 이유를 찾아 보고**한다.
- 사용자 **PC에 문제가 생길 수 있는 방법**은 쓰지 않고, **다른 방법**을 제시한다.
- 사용자가 묻기 전에 **스스로 더블체크**한다 (가격, 위치, 숫자, 화면).
- **"없다"·"안 된다"고 말하기 전에 모든 출처를 확인한다** (2.3.0 실수: 우리 모드 코드만 찾아보고 "알파 포켓몬이 없다"고 잘못 안내 → 사용자가 틀린 정보로 칭호를 빼기로 고름).
  - 확인할 곳: ① 우리 코드(`mod/`, `tools/`) ② 문서(`docs/`) ③ 설정(`pack/config/`) ④ 실제 모드 jar 안 (`javap`, `unzip -l`로 클래스·자원 확인).
  - 한 곳에서만 못 찾았으면 "없다"가 아니라 **"여기서는 못 찾았다"**고 말한다.
  - 기능이 없다는 이유로 사용자에게 선택을 물을 땐, 위 4곳을 확인한 **근거를 함께** 적는다.
- 공식 이름(포켓몬·도구·직함)은 **기억으로 쓰지 않는다** (고래왕국 → 고래왕 실수). 게임 언어 파일이나 검색으로 확인하고, 확인 못 하면 확인 못 했다고 적는다.

## 작업 순서

1. 요청을 항목별로 나눠 할 일 목록을 만든다.
2. 코드·생성기를 고친다. 자동 생성 파일은 직접 고치지 않고 `tools/*.py`를 고친 뒤 실행한다.
3. 모드(`mod/`)를 고쳤으면 `mod/install.sh`로 빌드해 모드팩에 넣는다.
4. 건물·지형(`tools/build_world.py`)을 고쳤으면 `load.mcfunction`의 `build:N`을 **먼저** +1 하고 실행한다 (짓기 끝에 저장하는 번호를 거기서 읽음. 둘이 다르면 서버를 켤 때마다 다시 지음).
   - 테스트(`tests/*.js`)의 `build: N`과 README도 같이 바꾼다.
5. `python3 tools/check_holes.py`로 건물 빈칸이 0개인지 확인한다.
6. 테스트 2개를 **동시에** 돌려 모두 통과시킨다: `tests/all.sh` (약 1분 20초).
7. 실제 클라이언트로 **바뀐 화면만** 찍어 확인한다 (`tools/shots.sh`).
   - 고정 대기(`wait`) 대신 조건 대기(`until 명령 ~ 정규식 ~ 최대ms`)를 쓴다.
   - UI는 **전체화면(1920×1080)** 기준으로 본다.
   - `GUI_SCALE=0 WIN=1920x1080 tools/shots.sh …` (GUI 크기 자동 = 사용자 화면과 같음).
   - **서버를 여러 번 껐다 켜지 않는다.** `KEEP=1`로 켜 둔 채 `/tmp/pokeserver-shots/queue/*.txt`에 단계 파일을 넣어 이어서 찍는다. 끝나면 `touch …/queue/stop`.
   - 접속 직후 25초는 입력이 씹힘 → 클릭·키 입력 전에 기다린다. `xdo type`은 띄어쓰기가 빠지니 `xdo key space`로 나눈다.
8. README와 **`docs/` 문서 3개**(작업규칙·서버안내·UI정리)를 고친다. 내용이 추가·변경될 때마다 반드시 보완한다.
9. `main`에 커밋·푸시한다 (packwiz 목록 `pack/index.toml` 갱신 포함).
10. GitHub 반영(약 5분)을 기다린 뒤, **실제 배포 방식**(`PROD=1 tools/shots.sh`)으로 서버를 열고 접속해 확인한다.
11. 짧게 보고한다: 한 것, 확인한 것, 못 한 것, **버전**.
   - 버전은 작업 묶음이 끝날 때마다 0.1씩 올린다 (`mod/gradle.properties`의 `mod_version`과 `pack/pack.toml`의 `version`을 같이). 0.2.0부터 시작.
12. 작성한 문서는 **아티팩트**(웹 페이지)로도 올려 링크를 보낸다.
   - 만들기: `python3 tools/docsite.py <출력.html> play|dev`. 관장 팀을 바꾸면 먼저 `python3 tools/teamdoc.py`.
   - 2개로 나눔: **잡켓몬 서버 문서**(서버원 배포용: 접속 방법·서버 안내·명령어) / **잡켓몬 서버 개발 문서**(서버장·개발: 서버 여는 법·운영자 명령어·UI 정리·관장·작업 규칙·스킬). 같은 모양.

## 지켜야 할 사항

### UI
- 기존 **어두운 반투명 색감**을 유지한다.
- 줄바꿈은 **단어 사이(띄어쓰기)**에서만. 단어 중간에서 끊지 않는다.
- UI를 바꾸면 `docs/UI정리.md`의 **실제 화면 사진**(`docs/ui/*.png`)도 다시 찍는다.
- 글자가 칸 밖으로 **넘치지 않게** 한다. 길면 "…"로 자르고 전체 글은 마우스를 올리면 보이게 한다.
- 화면이 좁아도 겹치지 않게 한다.

### 건물
- 건물에 **빈칸**이 없어야 한다 (`check_holes.py` 0개).
- 실내는 **밝게** (보이지 않는 빛 블록).
- 기존 건물과 비슷한 **품질·콘셉트**를 유지한다.

### 상점·가격
- 가격은 **다른 포켓몬 서버 가격을 직접 검색**해 참고한다. 못 찾으면 **못 찾았다고** 말한다.
- **몬스터볼 200원**을 기준으로 전체 가격을 비교한다.
- 사고팔기로 돈을 불리는 **구멍**이 없는지 본다 (판매가 < 구매가, 주민 교환 등).
- 상점 구매·판매 목록(가격·해금·물품)을 바꾸면 **매번** 상점 문서를 다시 만들어 올린다: `python3 tools/build_shop.py` → `python3 tools/shop_doc.py <scratch 폴더>` → 그 폴더의 `index.html`을 상점 문서(https://claude.ai/artifact/PTW2jXPoky47kGypJdTd45)에 `data.json`·`galmuri9.ttf`와 같이 다시 게시.

### 서버
- 렉을 줄인다: 무거운 명령은 여러 틱에 나눈다.
- 접속 확인은 **실제 배포 방식**으로 한다.

### 테스트 시간
- `tests/all.sh`: 데이터팩·모드 테스트를 동시에 실행.
- 데이터팩이 같으면 **지어 둔 월드를 재사용** (`tests/.cache`, shots는 `/tmp/pokeserver-shots/cache`).
- 모드 테스트는 "예전 월드 백업" 확인 때문에 매번 새 월드.
- 기다리는 반복(짓기 끝 등)은 시간이 다 되면 **바로 실패**시킨다. 그냥 넘어가면 문제는 못 잡고 시간만 버림.
- **특수 기믹 확인**: 서버를 `-Dpokeserver.gimmicklog=true`로 켜면(`SERVER_JAVA_OPTS=... tools/shots.sh`) 배틀 엔진의 메가·Z·다이맥스·테라스탈 줄이 서버 로그에 `[기믹]`·`[기믹 가능]`으로 남음 (`GimmickLogMixin`). 관장 쪽 교체 줄(`|switch|p2`)도 남아 선봉을 확인할 수 있음. 화면 대신 이 기록을 근거로 판단.
- **야생 Z크리스탈 확인**: `-Dpokeserver.zdrop=1`로 켜면 확률이 100%가 됨 (기본 0.05).
- **게임 시간을 기다리는 곳**(1초마다 도는 일, 10초 시간 초과, 짓기 등)은 실제 시간으로 기다리지 않고 `/tick sprint`로 빨리 돌린다 (테스트의 `ff(틱)`).
